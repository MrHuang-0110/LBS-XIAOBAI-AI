# doc/ — 项目记忆系统

本目录是「小白-Ai 主控固件」的**项目记忆库**：用 .md 文件持久记录框架、技术栈、踩坑与进度，供人和 AI 跨会话回忆。**所有会话开始时读取，所有 task 结束时更新。**

## 文件索引

| 文件 | 内容 | 更新时机 |
|---|---|---|
| `01-项目框架.md` | 硬件拓扑、软件分层、模块清单、数据流 | 架构/引脚/模块变化时 |
| `02-技术栈.md` | 芯片、工具链、库、外设、协议版本 | 工具链/依赖/协议升级时 |
| `03-踩坑记录.md` | 现象 → 原因 → 解决（含日期） | 每次遇到并解决坑后立即追加 |
| `04-开发进度.md` | 当前状态、版本历史、待办、已知问题 | 每个 task 完成后追加一行 |

## 更新规则

1. **先读后写**：改代码前先读相关分类文件，避免重复踩坑；改完同步更新对应文件。
2. **追加为主**：踩坑/进度以追加新条目为主，不重写历史；错误条目可标记 `[已过时]`。
3. **条目格式**（踩坑与进度）：`YYYY-MM-DD | 内容 | 状态`（状态：`进行中` / `已完成` / `已过时`）。
4. **代码注释与记忆同步**：代码里标注的坑（如"名称与模式不对应"）应能在这里找到对应条目。
5. **不写机密**：不含密钥/密码/个人隐私；涉及硬件时序的精确数值放代码注释，这里放结论。

## 项目规则（硬性门禁，详见 AGENTS.md）

每个 task / 每次代码改动必须依次通过：

1. **审查（Review）**：改动后用 code review 检查（正确性/边界/资源占用），重要改动另做安全审查
2. **TDD（测试先行）**：先写可验证的行为断言/验收清单，再实现；完成后逐条验证（编译 0 Error 0 Warning + 板上实测）
3. **Code Simple 优化**：用 code-simplifier 检查，删除重复、过度设计、死代码，保持最小可维护实现

未通过门禁的改动不得合入。
