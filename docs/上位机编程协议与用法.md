# 小白编程上位机 — 协议、指令、用法与发送周期

- 适用范围：Windows「小白编程」上位机（`tools/xiaobai_programmer`） ↔ PY32F030 主控固件（BLE 透传 ECB02）
- 权威实现：协议编解码 `src/xiaobai/protocol.py`、执行器 `src/xiaobai/executor.py`、传输层 `src/xiaobai/transport.py`、界面 `src/xiaobai/ui/`、积木 `src/xiaobai/resources/blocks.js`
- 协议契约（C 端/上位机共用）：`docs/BLE协议v2-编程模式.md`；本文侧重**上位机视角的用法与调度周期**
- 更新日期：2026-09-22

---

## 1. 总览

| 角色 | 职责 |
| --- | --- |
| 上位机（Windows Blockly） | 流程编排：循环/条件/等待/表达式求值；把每条动作翻译成一条 C2 指令；维护编程会话（ENTER_PROGRAM + 心跳）；显示状态与日志 |
| 主控 MCU | 指令执行器：校验参数、驱动电机/显示/语音、维护唯一等待型任务、完成回报（D2 DONE 立即 + 每 200ms 重报）、推送 D3 事件 |

要点：**编号只用于关联指令与 DONE，不做幂等/去重**；同一编号重复下发会重新执行。

---

## 2. 连接与 GATT

| 步骤 | 行为 |
| --- | --- |
| 扫描 | `BleakScanner.discover`，名字优先 `Spark_AI` / `XiaoBai` / `小白` / `ECB02` 等 |
| 连接 | 连接后枚举服务特征；写特征优先 `0000fff2-…`（ECB02 实测），通知特征优先 `0000fff1-…` |
| 探活 | 连上后发一次 `QUERY_STATUS`；默认写特征无响应则**逐个试其它可写特征**，成功即持久化 |
| 持久化 | 写/通知 UUID、最后地址存 `~/.xiaobai_programmer/config.json`，下次免扫描直连 |
| 断连 | 意外断开停止心跳、清会话标记；可自动重连（退避 1/2/4/8/8s） |
| 写方式 | 一律优先 `write_gatt_char(response=True)`（无确认写在本模块会静默丢包），失败才回退无确认 |

## 3. 帧格式（17 字节，固定）

```
偏移   0      1     2     3      4      5..14        15        16
      5A    SRC   DST   0A    TYPE   DATA[10]   CHECKSUM      A5
```

| 字段 | 值 |
| --- | --- |
| 帧头/帧尾 | `0x5A` / `0xA5` |
| SRC / DST | App→设备 `0x97 → 0x98`；设备→App `0x98 → 0x97` |
| 长度 | `0x0A`（10） |
| TYPE | `C1` 遥控 / `C2` 编程请求 / `D2` 响应 / `D3` 事件 |
| CHECKSUM | 字节 0..14 累加和低 8 位 |
| 多字节整数 | little-endian |

## 4. 指令集

### 4.1 C2 会话/查询指令（`seq = 0`）

| 操作码 | 名称 | 参数 | 说明 |
| --- | --- | --- | --- |
| `0x01` | ENTER_PROGRAM | — | 进入编程模式（幂等）；四灯跑马、播 ID 52 |
| `0x02` | ENTER_REMOTE | — | 进入遥控模式；退出编程会话 |
| `0x03` | HEARTBEAT | — | 会话心跳；不影响任务与 DONE 重报 |
| `0x04` | QUERY_STATUS | — | 查询状态（任意模式可用） |
| `0x05` | STOP_PROGRAM | — | 取消任务、刹停双电机，留在编程模式，不回报 |

### 4.2 C2 动作指令（`seq = 1..255` 循环）

| 操作码 | 名称 | 参数 | 是否等 DONE |
| --- | --- | --- | --- |
| `0x10` | MOTOR_TIME | `[motor, dir, ms0..ms3]` | 是（定时） |
| `0x11` | MOTOR_RUN | `[motor, dir]` | 否 |
| `0x12` | MOTOR_STOP | `[motor]` | 否 |
| `0x13` | MOTOR_POWER | `[level 1..3]` | 否 |
| `0x20` | MOVE_TIME | `[move, ms0..ms3]` | 是（定时） |
| `0x21` | MOVE_RUN | `[move]` | 否 |
| `0x22` | MOVE_STOP | — | 否 |
| `0x23` | MOVE_POWER | `[level 1..3]` | 否 |
| `0x30` | WAIT_IR | `[channel, cmp, threshold]` | 是（等事件） |
| `0x31` | READ_IR | — | 是（查询响应） |
| `0x40` | SHOW_EYE | `[eye 1..10]` | 否 |
| `0x41` | SHOW_NUM | `[num 0..100]` | 否 |
| `0x42` | SHOW_OFF | — | 否 |
| `0x50` | PLAY_VOICE | `[item 1..10]` | 否 |
| `0x51` | WAIT_VOICE | `[item 1..10]` | 是（等事件） |

取值：`motor` 0=左 1=右；`dir` 1=正转 2=反转；`move` 1=前进 2=左转 3=右转 4=后退；
`channel` 0=左 1=中 2=右；`cmp` 0=大于 1=小于；`level` 1/2/3 = 40%/70%/100%。

### 4.3 D2 响应（设备→App）

```
DATA = [seq, opcode, result, data0..data6]
```

| result | 含义 |
| --- | --- |
| `0x00` | OK |
| `0x01` | 参数非法 |
| `0x02` | 未知操作码 |
| `0x03` | 模式不允许 |

- **DONE**：需要回报的动作完成后立即发一次，之后每 **200ms** 重发同一帧，直到下一条指令/模式切换（心跳、查询不打断）。
- **QUERY_STATUS 响应** data 布局：`d0`=模式，`d1..d3`=红外 左/中/右（0–100），`d4..d5`=电池 mV（LE），`d6`=任务(高4位) | 故障(低4位)。
- **READ_IR 响应**：`d0..d2`=红外 左/中/右。

### 4.4 D3 事件（设备→App）

```
DATA = [event, counter, data0..data7]
```

| event | 名称 | data | 说明 |
| --- | --- | --- | --- |
| `0x01` | MODE_CHANGE | `d0`=新模式 `d1`=旧模式 | 模式切换 |
| `0x02` | PROGRAM_ABORT | `d0`=原因 `d1`=目标模式 | 1 心跳超时 / 2 BLE 断开 / 3 实体键 / 4 App 切模式 |
| `0x03` | IR_CHANGE | `d0..d2`=左/中/右 `d3`=掩码 | **仅编程模式推送**（避免占用遥控等模式的上行） |
| `0x04` | WAKE | — | 唤醒词 |
| `0x05` | SLEEP | — | 休眠 |
| `0x06` | LOW_BATTERY | `d0`=1进入/0恢复 `d1..d2`=mV | 低电量翻转 |
| `0x07` | PROTOCOL_ERROR | `d0`=错误码 | 1 溢出 / 2 校验失败 / 3 未知操作码 / 4 非法参数 |

### 4.5 模式 / 任务 / 故障码

| 模式 | 值 | | 任务（QUERY_STATUS 高4位） | 值 | | 故障（低4位） | 值 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 语音 | 0 | | 无 | 0 | | 心跳丢失 | `0x1` |
| 动力 | 1 | | 定时电机 | 1 | | 未知操作码 | `0x2` |
| 感应 | 2 | | 等待红外 | 2 | | 非法参数 | `0x4` |
| 遥控 | 3 | | 等待词条 | 3 | | | |
| 编程 | 4 | | | | | | |

## 5. 发送周期与调度（重点）

所有 BLE 写都经过同一个串行写队列，按下面规则调度。

### 5.1 心跳（编程会话）

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 调度粒度 | 50ms | 睡眠式循环；事件循环卡顿恢复后**不会补发**积压心跳 |
| 空闲周期 | 300ms | 300ms 内没有前台指令时按此周期发 `HEARTBEAT` |
| 前台跳过 | — | 前台 C2 刚发出（300ms 内）时跳过本轮冗余心跳 |
| 硬上限 | **600ms** | 无论前台多忙，显式心跳间隔不超过 600ms（兼容只认心跳的旧固件） |
| 单实例 | — | 同时最多一个心跳待发；`start_heartbeat()` 幂等 |
| 首次心跳 | +300ms | 进入编程模式时 ENTER_PROGRAM 已续期，不立刻补心跳 |

> 新固件里"结构+语义有效的 C2"也算会话活跃；上位机仍保留 ≤600ms 显式心跳，兼容旧固件。

### 5.2 状态查询

| 项目 | 值 |
| --- | --- |
| 轮询周期 | 1000ms，**仅「状态」页可见时** |
| 进页 | 立即查询一次，然后按周期 |
| 其它页面 | 0 轮询（直接控制/Blockly 页不产生后台查询） |
| 程序运行中 | 不发周期查询（避免与 DONE/动作抢通道） |
| 不叠加 | 上一条 `QUERY_STATUS` 未回时跳过；超时/断连后 pending 自动清理 |
| 单次超时 | 3.0s |

### 5.3 写保护窗（ECB02 收发保护）

| 保护 | 值 | 说明 |
| --- | --- | --- |
| TX → TX | ≥30ms | 相邻两次写之间 |
| 通知 → TX | ≥30ms | 收到 D2/D3 通知后再写 |
| 后台饥饿保护 | 250ms | 后台帧（心跳/查询）等待超过 250ms 后不再被后来的前台帧插队 |
| 写方式 | 带确认优先 | `response=True`；失败才回退无确认 |

### 5.4 写队列优先级

| 优先级 | 帧 |
| --- | --- |
| 前台（插到未超时后台帧之前，同级 FIFO） | 按钮动作、程序动作、停止、`ENTER_PROGRAM` / `ENTER_REMOTE` |
| 后台 | 心跳、`QUERY_STATUS`、`READ_IR`（表达式求值用） |

效果：按按钮/执行动作时不会排在已等待的心跳或状态查询后面；后台帧也不会被连续前台帧无限饿死。

### 5.5 各指令等待超时（上位机侧）

| 指令 | 超时 |
| --- | --- |
| `request()` 默认（动作等 DONE） | 5.0s |
| `QUERY_STATUS` / `READ_IR` | 3.0s |
| `MOTOR_TIME` / `MOVE_TIME` | 动作时长 + 3.0s |
| `WAIT_IR` / `WAIT_VOICE` | 60s（`DEFAULT_WAIT_TIMEOUT`） |
| 心跳发送失败 | 只记日志，不中断执行 |

### 5.6 与固件周期的配合

| 固件侧 | 值 |
| --- | --- |
| 会话超时 | 1000ms 无有效 C2 → 刹停、退出编程模式、播 ID 53 |
| DONE 重报 | 立即 + 每 200ms，直到新指令 |
| 等待红外采样 | 20ms/次，连续 3 次满足才算完成 |
| MCU RX → TX | ≥30ms；相邻回帧 ≥10ms |
| MCU 发送队列 | 4 帧，主循环非阻塞调度 |
| 遥控模式 | 无键帧=松手立即刹；无帧超时 2s 兜底；PF3 掉线立即刹 |

### 5.7 一次典型运行的时序

```
连接 → QUERY_STATUS 探活（3s 内）
     → ENTER_PROGRAM（前台）
     → 心跳：空闲 300ms / 前台忙时 600ms 上限
动作：C2(seq=n) ──30ms 保护窗──> 写
     ← D2 DONE(seq=n)（可能先到/重报，按 seq+opcode 匹配）
     → 下一条动作…
停止：STOP_PROGRAM（前台，插队）→ 取消任务/刹停 → 不再有 DONE
中止：← D3 PROGRAM_ABORT → 立即停止执行并提示
```

## 6. 页面与会话生命周期

| 页面/动作 | 行为 |
| --- | --- |
| 设备连接 | 扫描/连接/离线演示；连接成功后自动探活并记录可用写特征 |
| 直接控制 | 进入本页自动确保编程会话（ENTER_PROGRAM + 心跳）；每个按钮动作前再次确保；停止/中止后下次动作自动重建会话 |
| Blockly 编程 | 切到本页自动确保编程会话；运行前确保会话，然后按 AST 执行 |
| 状态 | 进页立即查询 + 每 1s 刷新（模式/红外/电量/任务/故障） |
| 协议日志 | 记录每条发送指令、D2/D3 事件与错误 |
| 停止程序 | 始终可用；`STOP_PROGRAM` + 刹停，前台优先级不合并、不延后 |
| 进入手机遥控 | 停止心跳、发 `ENTER_REMOTE`；会话标记清空 |
| 断开连接 | 停止心跳、清会话标记；重连后按当前页重建 |

会话去重：同一连接内只发一次 `ENTER_PROGRAM`；发送失败可重试；设备中止（D3）或上位机停止后再动作会重新进入。

## 8. 表达式积木

| 积木 | AST | 求值时机 |
| --- | --- | --- |
| 左/中/右 红外值 | `{type:"ir",channel}` | 每次求值时发 `READ_IR`（3s 超时） |
| 电量（mV） | `{type:"battery"}` | 发 `QUERY_STATUS` 读 `battery_mv` |
| 设备模式号 | `{type:"mode"}` | 发 `QUERY_STATUS` 读 `mode` |
| 算术 `+ - * /` | `{type:"math",op,a,b}` | 本地；除零报错 |
| 比较 `== != < <= > >=` | `{type:"cmp",op,a,b}` | 本地 |
| 与/或/非 | `{type:"and/or/not"}` | 本地，短路求值 |

「显示数字」接表达式时：运行时求值 → 四舍五入取整 → **限幅 0–100** → 下发 `0x41`。

## 9. 工程文件 `.xbprog`

```json
{
  "format": "xiaobai-program",
  "version": 1,
  "name": "示例",
  "saved_at": "2026-09-22T12:00:00",
  "workspace": { "...Blockly 序列化..." },
  "program": { "format": "xiaobai-program-ast", "version": 1, "statements": [ ... ] }

```

加载时**以工作区为权威重新解析**：被手工篡改/夹带未知块的 AST 会被拒绝。

| `repeat` / `while` / `if` | `times` `body` / `until` `cond` `body` / `cond` `then` `else` |

## 10. 程序执行语义

| 语义 | 说明 |
| --- | --- |
| 编号分配 | 动作 `1..255` 循环；会话/心跳/查询固定 `seq=0` |
| DONE 匹配 | 按 `(seq, opcode)` 匹配；200ms 重报/迟到响应会被忽略并记日志 |
| 抢占 | 设备收到任意新动作立即停止旧 DONE 重报并取消旧任务（必要时刹停其电机） |
| 等待型任务 | 设备同一时刻只有一个（定时电机/等待红外/等待词条） |
| `STOP_PROGRAM` | 上位机停止：取消任务、刹停、**留在编程模式**；不产生 DONE |
| D3 中止 | `PROGRAM_ABORT` → 执行器立即抛错中止并提示原因/目标模式 |
| 错误响应 | D2 `result != 0`（查询状态除外）→ 抛执行错误并停止程序 |
| 循环保护 | 语句总数 ≤500、嵌套 ≤8 层、重复 ≤1000、while ≤10000 次 |
| 本地等待 | 0–600s，不占用设备任务 |

## 11. 使用步骤

1. 安装/启动（首次）：
   ```bat
   cd /d E:\LBS-XIAOBAI-AI\tools\xiaobai_programmer
   python -m pip install -r requirements.txt   rem 或按 README 用清华源
   run_dev.bat
   ```
2. 设备连接页：扫描 → 选 `Spark_AI` → 连接（首次自动发现并记住 UUID）；无硬件可点「离线演示（模拟设备）」。
3. 直接控制页：单电机/组合移动、功率档、关闭显示、停止程序；进入本页会自动建立编程会话。
4. Blockly 编程页：拖积木 → 运行；切到本页自动 `ENTER_PROGRAM`（四灯跑马、播 ID 52）。
5. 状态页：进入即查一次，之后每 1s 刷新（只有本页会周期查询）。
6. 停止：任意页面的「停止」按钮都可用（`STOP_PROGRAM` + 刹停，不排队）。
7. 工程：保存/加载 `.xbprog`（工作区 + AST 一起存，加载重新校验）。

## 12. 排障速查

| 现象 | 排查 |
| --- | --- |
| 连接后无响应 | 确认设备已烧录 BLE v2 固件；看日志里试过的写特征；设备是否被手机占用 |
| 按钮响应慢 | 用探针测延时（见 §13）；确认没有其它中心连接；检查写保护窗与心跳是否正常 |
| 程序不合法 | 弹窗会给出具体块/参数（如"显示数字: 数值必须在 0-100"、"输入 NUM 必须是数字"） |
| 等待红外/词条超时 | 默认 60s；确认阈值/通道、ASR 词条 ID 是否匹配 |
| DONE 迟到/重复 | 正常现象（设备 200ms 重报）；日志会记录"已完成或无等待" |
| 设备中途停止 | 看 D3 `PROGRAM_ABORT` 原因：1 心跳超时 / 2 BLE 断开 / 3 实体键 / 4 切模式 |
| 遥控长按顿挫 | 见 `doc/03-踩坑记录.md`（接收连续流、松开判定、PF3 兜底均已修复） |

## 13. 诊断工具（无界面探针）

`tools/ble_probe.py`（Windows Python + bleak，不依赖 PySide6）：

```bat
python tools\ble_probe.py                     # 扫描 Spark_AI 并连接，发 ENTER_PROGRAM + 心跳
python tools\ble_probe.py --seconds 12        # 观察 D2/D3
python tools\ble_probe.py --address AA:BB:..  # 直连
python tools\ble_probe.py --hunt 8            # 猎手：试探信号最强的 8 个设备
python tools\ble_probe.py --latency --samples 120 --save result.json --label baseline
python tools\ble_probe.py --latency --bg-policy legacy   # 固定 300ms 心跳（优化前基线）
```

`--latency` 四场景（idle / heartbeat_300ms / poll_1s / mixed_200ms）统计 `queue_wait`（等锁排队）、
`guard_wait`（30ms 保护窗）、`write`、`rtt` 的 min/P50/P95/max 与丢帧；结果 JSON 可前后对比。
